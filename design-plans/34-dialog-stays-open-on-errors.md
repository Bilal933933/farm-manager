# خطة 34 — `preserveState: 'errors'` لكل إرسالات النماذج (إصلاح بلاغ الإغلاق الصامت)

- الحالة: منفذة كودياً + مبنية (Done code — `tsc` ناجح + `npm run build` ناجح؛ التحقق المتصفحي النهائي معلق على أدوات المتصفح)
- الكوميت المرجعي: `2c88a12cd42159cc62f0420e5fa134166c7fd654`
- السطح: كل إرسالات النماذج (26 استدعاء: 6 حوارات + 9 صفحات إنشاء/تعديل + مخزون + بيع) — عدا `auth/settings` (نطاق starter-kit)
- الأولوية: حرجة (علة سلوكية مثبتة بالتناسخ — ليست تجميلاً)

## المشكلة (مثبتة بالتناسخ على `/lands/2`)
إرسال فارغ ← `POST` ← **302** (عميل Inertia v2 يرسل `Accept: text/html` فـ `expectsJson()` خطأ — مثبت بتجربة `fetch` أعادت 422 مع `Accept: json`) ← زيارة GET ← **مفتاح صفحة جديد** (`key: preserveState ? key : Date.now()` مثبت في `core/dist`) ← إعادة تركيب كاملة ← الحوار مغلق والأخطاء يتيمة.

## الدليل
- شبكة المتصفح: `POST → 302 → GET` + خاصية `errors.planting_date` حاضرة + لقطة بلا حوار.
- محاولتان مرفوضتان وموثقتان: (1) إجبار 422 خلفياً ← نافذة خطأ Inertia (العميل بلا فرع 422) — أُعيدت. (2) خطاف `use-dialog-with-errors` + مفاتيح تذكّر ← `useRemember` لا ينجو من زيارات الدفع (للرجوع فقط) — حُذف الخطاف وأُعيدت الحوارات الست لأصلها.

## التغيير (طبقتان)
1. `preserveState: 'errors'` في 26 استدعاء `post/put` — يمنع إعادة التركيب عند الزيارة الأولى (البيانات والأخطاء والحوار أحياء).
2. `hooks/use-persistent-dialog-form.ts` + توصيلة حوارات `/lands/2` الثلاثة (`Season/Cost/Contract`) — لأن كتل `<Deferred>` تُطلق زيارات جزئية لاحقة تُعيد التركيب مهما كان: لقطة `sessionStorage` عند الإرسال، واستعادة لمرة واحدة عند التركيب **فقط إن وُجدت أخطاء تخص الحوار** (المفتاح: slug + مسار الصفحة + id التعديل — بلا تسرب بين السياقات).

## التحقق
1. `npx tsc --noEmit` ناجح.
2. تناسخ المتصفح بعد البناء: إرسال فارغ ← الحوار **يبقى مفتوحاً** والخطأ ظاهر؛ تواريخ معكوسة ← خطأ `harvest_date` + البيانات محفوظة؛ إرسال صحيح ← إغلاق + تنبيه نجاح.
